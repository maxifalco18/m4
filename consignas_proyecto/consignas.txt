Contexto del proyecto y rol del estudiante

Te desempeñas como Ingeniero de Datos en una organización que está migrando hacia una arquitectura moderna basada en la nube para gestionar grandes volúmenes de datos en crecimiento constante. La empresa necesita una solución escalable que le permita integrar información proveniente de diversas fuentes, con el fin de mejorar la toma de decisiones basada en datos confiables y actualizados.

Tu rol consiste en diseñar e implementar un pipeline de tipo ETLT sobre una arquitectura de Data Lake, utilizando almacenamiento en la nube y formatos de archivo eficientes. Serás responsable de integrar datos con herramientas como Airbyte, procesarlos de forma distribuida mediante Apache Spark, y orquestar el flujo completo con Apache Airflow. Además, deberás automatizar algunas tareas clave del pipeline con GitHub Actions, aplicar buenas prácticas de seguridad en la nube y optimizar el rendimiento y los costos asociados al procesamiento y almacenamiento de datos.

A modo de guía, se sugiere que el análisis se oriente a responder, al menos parcialmente, interrogantes como los siguientes:

¿Cuáles son los productos más vendidos por categoría y cómo varía su demanda a lo largo del tiempo?

¿Qué clientes presentan mayor frecuencia de compra y cuál es su ticket promedio mensual?

¿Qué tiendas o regiones generan los mayores ingresos y cómo se comportan frente a la estacionalidad?

¿Qué proporción de ventas proviene de clientes nuevos frente a clientes recurrentes?

¿Qué relación existe entre el precio promedio y el volumen de ventas en cada categoría?

¿Qué productos presentan mayores márgenes de rentabilidad considerando costos e ingresos?

¿Cómo varía el desempeño de ventas en función del canal o método de pago utilizado?

¿Qué patrones o anomalías pueden detectarse en las ventas en tiempo real (por ejemplo, picos de demanda o caídas abruptas)?

¿Cómo impactan las promociones o descuentos en las ventas totales y en la rentabilidad por producto?

¿Qué combinaciones de producto y cliente podrían identificarse como oportunidades para campañas de recomendación o fidelización?

Estas preguntas no son obligatorias, pero servirán como guía para orientar el diseño del pipeline y la construcción de la capa analítica final, garantizando que las transformaciones, integraciones y procesos implementados respondan a necesidades reales del negocio.

INGESTA DE DATOS CON AIRBYTE

Contexto del proyecto y rol del estudiante

Con la arquitectura definida, el foco pasa a construir el componente de ingesta del pipeline. En este avance, configuras Airbyte para integrar datos desde APIs públicas y bases PostgreSQL, cargándolos en la capa raw del Data Lake.

Como responsable de esta etapa, debes garantizar la conectividad, validar los datos almacenados y documentar las decisiones de configuración. Tu trabajo habilita el flujo inicial de datos hacia el sistema, cumpliendo con criterios de frecuencia, consistencia y trazabilidad que permitirán escalar hacia flujos de transformación posteriores.

¿Empezamos?

En este punto, vamos a avanzar con los siguientes pasos:

Consigna
Configuración de Airbyte Cloud (Free Tier) como componente de ingesta del pipeline ELT, configurando conectores desde una API públicay una base de datos PostgreSQL pública, ambos dirigidos hacia la capa raw/ del bucket S3 en AWS. Se documentan las conexiones, frecuencia de sincronización y esquema de los datos extraídos

Configuración del conector desde API pública utilizando el conector HTTP genérico de Airbyte para extraer datos. La extracción se limita a una ejecución manual por día durante el período de prueba gratuita para ajustarse al límite de sincronizaciones del Free Tier. El destino de los datos es el bucket S3 particionado.

Configuración del conector desde base de datos pública PostgreSQL. Se establece una conexión segura mediante credenciales de solo lectura y se sincroniza la tabla hacia S3. Se prioriza sincronización completa inicial y luego incremental.

Validación de que los datos son correctamente almacenados en el S3 en el formato esperado (i.e., Parquet) y en la ubicación definida.

Streaming

Contexto del proyecto y rol del estudiante

En esta fase final, das un paso hacia el procesamiento en tiempo real. Despliegas Apache Kafka y configuras Spark Structured Streaming para capturar eventos en vivo y consolidarlos junto con los datos batch en una capa gold unificada.

En tu rol, aseguras que el sistema pueda operar en una arquitectura Lambda, integrando flujos batch y streaming sin perder consistencia. Esta integración permite que la organización tome decisiones basadas en datos tanto históricos como en tiempo real, completando una solución moderna, escalable y robusta.

📝CONSIGNAS
Despliegue de Apache Kafka en una instancia EC2 utilizando Docker Compose, habilitando la creación de topics para la recepción de datos en tiempo real (requiere validación).

Configuración de un consumidor Spark Structured Streaming, que consuma datos desde Kafka, aplique transformaciones básicas y los escriba en la capa raw-streaming del bucket S3 en formato Parquet.

Implementación de transformaciones adicionales con PySpark que enriquezcan los datos en streaming utilizando datos existentes de la capa processed de origen batch  y escriban los resultados en una capa processed-streaming.

Consolidación de los datos procesados (batch y streaming) en una capa gold unificada, que permita a los analistas y científicos consumir información confiable e integrada, indistintamente de la naturaleza de origen de los datos.

Actualización del diagrama de arquitectura del pipeline para reflejar claramente el nuevo componente de ingesta en tiempo real, sus interacciones con las capas del Data Lake, y cómo se orquesta en conjunto con las tareas batch.

#CRITERIOS DE EVALUACION

CATEGORÍA A EVALUAR | REQUERIMIENTO POR CATEGORÍA | EXCELENTE | SATISFACTORIO | INSUFICIENTE

Diseño de Arquitectura del Data Lake (10 pts)
Requerimiento: Elaborar un diseño de arquitectura completo y justificado, con diagrama, capas definidas y stack tecnológico.
- Excelente: Diseño detallado, bien justificado, diagrama claro con herramientas específicas, y stack adecuadamente seleccionado.
- Satisfactorio: Diseño adecuado pero con justificaciones generales o sin detalle de herramientas/tecnologías.
- Insuficiente: Diseño incompleto, sin diagrama o sin definición clara de capas o herramientas.

Ingesta de datos con Airbyte (10 pts)
Requerimiento: Configurar conectores desde una API pública y una base de datos PostgreSQL hacia S3, con validación de datos.
- Excelente: Conectores correctamente configurados, ingesta validada y documentada, uso correcto del conector HTTP y PostgreSQL.
- Satisfactorio: Conectores configurados pero con validación parcial o documentación escasa.
- Insuficiente: Ingesta incorrecta o sin validación/documentación de las conexiones.

Procesamiento con PySpark (15 pts)
Requerimiento: Transformar datos en Spark con código optimizado y responder preguntas de negocio.
- Excelente: Transformaciones relevantes, código optimizado (particionamiento, caché, sin shuffles innecesarios), y resultados claros.
- Satisfactorio: Transformaciones funcionales pero con optimización limitada o sin conexión clara a preguntas.
- Insuficiente: Código incorrecto, sin optimización ni conexión con las preguntas de negocio.

Orquestación del pipeline con Airflow (10 pts)
Requerimiento: Implementar un DAG que integre Airbyte, Spark, y gestione capas del Data Lake con control de errores.
- Excelente: DAG completo, bien estructurado, manejo de dependencias y errores, integración correcta entre componentes.
- Satisfactorio: DAG funcional pero con estructura mejorable o manejo básico de errores.
- Insuficiente: DAG incompleto o sin conexión entre tareas clave.

Streaming con Kafka y Spark (10 pts)
Requerimiento: Implementar un pipeline de streaming funcional.
- Excelente: Pipeline correctamente implementado, con integración Kafka-Spark, procesamiento en tiempo real y manejo de offsets.
- Satisfactorio: Implementación básica funcional pero con limitaciones o sin robustez.
- Insuficiente: Sin implementación o integración del pipeline de streaming.
